# Creating the host VMs (Linux and Windows)

Document timestamp: 2026-11-15T01:28:16Z

A bridge must stay online around the clock, so it belongs on a small always-on virtual machine rather than a laptop. This guide creates that VM on your own hardware or in a cloud, for a Linux guest and for a Windows guest, and ends where the [releases guide](RELEASES_2026-11-15T012816Z.md) begins.

## Sizing and network

| | Minimum | Recommended |
| --- | --- | --- |
| Linux guest (Ubuntu Server 24.04 LTS) | 1 vCPU, 1 GB RAM, 10 GB disk | 2 vCPU, 2 GB RAM, 20 GB disk |
| Windows guest (Windows 11 / Server 2022 or 2025) | 2 vCPU, 4 GB RAM, 64 GB disk | 2 vCPU, 8 GB RAM, 80 GB disk |

Only **outbound** HTTPS (TCP 443) is needed, to Discord, WhatsApp and the package registries. Open no inbound ports except SSH (22) or RDP (3389) for your own administration, restricted to your IP address. Linux is the cheaper and lighter choice; use Windows only if that is what you already operate.

## Linux VM

### Option A — Multipass (Linux, macOS or Windows host; simplest)

Install Multipass on a Linux host:

```bash
sudo snap install multipass
```

Create the VM with the script (downloads Ubuntu 24.04, applies cloud-init, clones your repository into `/opt/wa2dc-unified`):

```bash
bash deploy/linux/create-linux-vm_v1.0.0_2026-11-15T012816Z.sh --backend multipass --repo-url https://github.com/<owner>/wa2dc-unified.git
```

Or by hand:

```bash
multipass launch 24.04 --name wa2dc --cpus 2 --memory 2G --disk 20G
```

```bash
multipass shell wa2dc
```

### Option B — KVM/libvirt (Linux host, production)

Check that the CPU supports virtualisation (a number above 0) and install the hypervisor:

```bash
grep -Ec '(vmx|svm)' /proc/cpuinfo
```

```bash
sudo apt-get update && sudo apt-get install -y qemu-kvm libvirt-daemon-system virtinst qemu-utils
```

```bash
sudo usermod -aG libvirt "$USER" && newgrp libvirt
```

Create an SSH key if you have none, then the VM:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N ""
```

```bash
bash deploy/linux/create-linux-vm_v1.0.0_2026-11-15T012816Z.sh --backend kvm --ssh-key ~/.ssh/id_ed25519.pub --repo-url https://github.com/<owner>/wa2dc-unified.git
```

Find its address and log in (cloud-init needs about a minute on first boot):

```bash
sudo virsh domifaddr wa2dc
```

```bash
ssh ubuntu@<ip-address>
```

Make it start with the host:

```bash
sudo virsh autostart wa2dc
```

### Option C — VirtualBox (any desktop host)

Download `ubuntu-24.04-live-server-amd64.iso` from ubuntu.com, then:

```bash
VBoxManage createvm --name wa2dc --ostype Ubuntu_64 --register
VBoxManage modifyvm wa2dc --cpus 2 --memory 2048 --nic1 nat --firmware efi
VBoxManage createmedium disk --filename "$HOME/VirtualBox VMs/wa2dc/wa2dc.vdi" --size 20480
VBoxManage storagectl wa2dc --name SATA --add sata
VBoxManage storageattach wa2dc --storagectl SATA --port 0 --type hdd --medium "$HOME/VirtualBox VMs/wa2dc/wa2dc.vdi"
VBoxManage storageattach wa2dc --storagectl SATA --port 1 --type dvddrive --medium ~/Downloads/ubuntu-24.04-live-server-amd64.iso
VBoxManage startvm wa2dc
```

Complete the Ubuntu installer in the window that opens and tick **Install OpenSSH server**.

### Option D — cloud

Azure:

```bash
az group create --name wa2dc-rg --location westeurope
az vm create --resource-group wa2dc-rg --name wa2dc --image Ubuntu2404 --size Standard_B2s --admin-username azureuser --generate-ssh-keys --public-ip-sku Standard
```

AWS (replace the key pair and security group with your own; the SSM parameter resolves the current Ubuntu 24.04 image):

```bash
aws ec2 run-instances --image-id resolve:ssm:/aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id --instance-type t3.small --key-name <key-pair> --security-group-ids <sg-id> --block-device-mappings 'DeviceName=/dev/sda1,Ebs={VolumeSize=20,VolumeType=gp3}' --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=wa2dc}]'
```

### Inside the Linux VM

```bash
sudo apt-get update && sudo apt-get -y upgrade
```

If the repository was not cloned by cloud-init:

```bash
sudo git clone https://github.com/<owner>/wa2dc-unified.git /opt/wa2dc-unified
```

```bash
cd /opt/wa2dc-unified && sudo bash deploy/linux/install-linux_v1.0.0_2026-11-15T012816Z.sh --bridge main
```

Basic hardening (allow SSH, deny other inbound traffic, keep security updates automatic):

```bash
sudo ufw allow OpenSSH && sudo ufw --force enable
```

```bash
sudo dpkg-reconfigure -plow unattended-upgrades
```

## Windows VM

### Option A — Hyper-V (Windows 10/11 Pro or Windows Server host)

Enable Hyper-V from an elevated PowerShell, then reboot:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
```

On Windows Server use:

```powershell
Install-WindowsFeature Hyper-V -IncludeManagementTools -Restart
```

Download a Windows 11 or Windows Server ISO from microsoft.com (evaluation ISOs are free for testing; production use needs a licence), then create the VM. The script builds a Generation 2 VM with Secure Boot and a virtual TPM (required by Windows 11), attaches the ISO and opens the console:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\deploy\windows\create-windows-vm_v1.0.0_2026-11-15T012816Z.ps1 -IsoPath C:\ISO\Win11_x64.iso
```

Press a key when "Press any key to boot from CD or DVD" appears and complete Windows Setup. The same script creates a Linux guest on Hyper-V:

```powershell
.\deploy\windows\create-windows-vm_v1.0.0_2026-11-15T012816Z.ps1 -IsoPath C:\ISO\ubuntu-24.04-live-server-amd64.iso -Guest Linux -MemoryGB 2 -DiskGB 20
```

### Option B — VirtualBox

```bash
VBoxManage createvm --name wa2dc-win --ostype Windows11_64 --register
VBoxManage modifyvm wa2dc-win --cpus 2 --memory 4096 --nic1 nat --firmware efi --tpm-type 2.0
VBoxManage modifynvram wa2dc-win inituefivarstore
VBoxManage modifynvram wa2dc-win enrollmssignatures
VBoxManage modifynvram wa2dc-win secureboot --enable
VBoxManage createmedium disk --filename "$HOME/VirtualBox VMs/wa2dc-win/wa2dc-win.vdi" --size 65536
VBoxManage storagectl wa2dc-win --name SATA --add sata
VBoxManage storageattach wa2dc-win --storagectl SATA --port 0 --type hdd --medium "$HOME/VirtualBox VMs/wa2dc-win/wa2dc-win.vdi"
VBoxManage storageattach wa2dc-win --storagectl SATA --port 1 --type dvddrive --medium ~/Downloads/Win11_x64.iso
VBoxManage startvm wa2dc-win
```

### Option C — cloud

Azure (you are prompted for the administrator password):

```bash
az vm create --resource-group wa2dc-rg --name wa2dc-win --image Win2022Datacenter --size Standard_B2ms --admin-username wa2dcadmin --public-ip-sku Standard
az vm open-port --resource-group wa2dc-rg --name wa2dc-win --port 3389 --priority 1000
```

Then restrict the RDP rule's source to your own address in the network security group.

### Inside the Windows VM

Install pending updates (Settings → Windows Update), then from an elevated PowerShell:

```powershell
winget install --id Git.Git --exact --silent --accept-package-agreements --accept-source-agreements
```

Open a new elevated PowerShell so `git` is on the PATH:

```powershell
git clone https://github.com/<owner>/wa2dc-unified.git C:\wa2dc-unified
```

```powershell
Set-Location C:\wa2dc-unified; Set-ExecutionPolicy -Scope Process Bypass -Force; .\deploy\windows\install-windows_v1.0.0_2026-11-15T012816Z.ps1 -Bridge main
```

Windows Server 2022 does not ship winget; install "App Installer" from https://aka.ms/getwinget first, or use Windows Server 2025 / Windows 11 where it is built in.

## After the VM exists

Continue with section 4 (Configure) of the [releases guide](RELEASES_2026-11-15T012816Z.md). Take a snapshot or backup **after** WhatsApp is linked, and treat it as a secret: it contains the WhatsApp session.

| Hypervisor | Snapshot command |
| --- | --- |
| Multipass | `multipass stop wa2dc && multipass snapshot wa2dc` |
| KVM | `sudo virsh snapshot-create-as wa2dc linked` |
| Hyper-V | `Checkpoint-VM -Name wa2dc -SnapshotName linked` |
| VirtualBox | `VBoxManage snapshot wa2dc take linked` |

## What was and was not tested

The Linux scripts were syntax-checked and exercised with `--dry-run` in the build environment; the PowerShell scripts could not be executed there (no Windows, no PowerShell). CI (`unified-ci.yml`) parses both on every push. Run them with `--dry-run` / `-WhatIf` first on your own host.
